# D&D Campaign Wiki

A ready-to-use template for a tabletop RPG campaign wiki: session recaps, story arcs,
house rules and magic items, published as a website for your players.

Built on [MkDocs Material](https://squidfunk.github.io/mkdocs-material/), with a few small
hooks that turn plain Markdown session notes into timelines automatically. Write in any
editor (it works especially well with [Obsidian](https://obsidian.md/)), push to GitHub,
and the site updates itself.

**[See the live demo](https://mbalasso.github.io/dnd-campaign-wiki/)**, built from the example
campaign included in this repository.

## Features

- **Automatic session timelines.** Drop a `<!-- TIMELINE -->` marker in a page and get a
  table of every session in that folder, sorted by date and linked.
- **Story arcs.** Run several parties in the same world? Tag each session with one or more
  arcs and get a separate timeline per arc with `<!-- TIMELINE:ARC -->`. Sessions where
  parties meet show up in every arc they belong to.
- **"Last session" link.** A `<!-- LAST_SESSION -->` marker on the home page always points
  to the most recent recap, so players find it before the next game.
- **Session subtitles.** In-game date, real-world date and party appear under each
  session title, read straight from the page's frontmatter.
- **Cover images.** Add `cover:` to any page for a full-width header image.
- **Light and dark theme, full-text search, mobile friendly** (thanks to MkDocs Material).
- **Free hosting on GitHub Pages**, deployed on every push by the included workflow.

## Quick start

1. Click **Use this template** on GitHub to create your own copy (or fork/clone it).
2. Install the dependencies (Python 3.10+):

   ```bash
   pip install -r requirements.txt
   ```

3. Preview the site locally at http://127.0.0.1:8000:

   ```bash
   mkdocs serve
   ```

4. Edit `mkdocs.yaml`: set `site_name`, `site_url`, `repo_url` and your arc codes
   (see [Configuring mkdocs.yaml](#configuring-mkdocsyaml)).
5. Start writing in `docs/`: it contains an empty skeleton ready for your campaign, with
   short instructions in comments that don't show on the site.

The example campaign stays in `example-docs/` as a reference, untouched by your work.
Preview it at any time with:

```bash
mkdocs serve -f example.yaml
```

Once you no longer need it, you can delete `example-docs/` and `example.yaml`.

## Configuring mkdocs.yaml

`mkdocs.yaml` configures your wiki (`example.yaml` only configures the example campaign
and can be ignored). This chapter covers the settings most campaigns change, and many
only need the first two sections.

While `mkdocs serve` is running, the site reloads after every save, so you can try changes
as you go. YAML is indentation-sensitive: use spaces, never tabs, and keep nested keys
aligned as in the original file.

### 1. Site identity

```yaml
site_name: My Campaign Wiki
site_url: https://YOUR-USERNAME.github.io/YOUR-REPO/
repo_url: https://github.com/YOUR-USERNAME/YOUR-REPO
```

| Key         | What it does |
|-------------|--------------|
| `site_name` | Title shown in the header and in the browser tab. |
| `site_url`  | Public address of the site. For GitHub Pages it is `https://<user>.github.io/<repo>/`, with the trailing slash. Used to build correct links and the sitemap. |
| `repo_url`  | Adds a link to your GitHub repository in the header. Delete the line if you don't want players to see it. |

### 2. Campaign options

These options are specific to this template and live under `extra:`:

```yaml
extra:
  # arcs: [MAIN]
  date_format: "%Y-%m-%d"
```

- **`arcs`** (optional, commented out by default): the list of valid arc codes, matching
  the `arc:` field of your sessions and the `<!-- TIMELINE:CODE -->` markers. Once you
  uncomment it, a session tagged with an unknown arc makes the build fail with a clear
  error, so a typo never silently drops a session from a timeline. Codes may use letters,
  digits, `_` and `-`.
- **`date_format`** (optional): how real-world dates are displayed, as a Python
  [strftime](https://docs.python.org/3/library/datetime.html#strftime-and-strptime-format-codes)
  format. Use `"%d/%m/%Y"` for European style or `"%B %d, %Y"` for "March 21, 2026".
  Dates in frontmatter are always written as `YYYY-MM-DD`, whatever the display format.

### 3. Language

The site interface (search box, navigation labels, footer) follows `theme.language`.
Search uses its own setting for word stemming. Change both together:

```yaml
theme:
  language: it     # interface language

plugins:
  - search:
      lang: it     # search language
```

See the [languages supported by Material](https://squidfunk.github.io/mkdocs-material/setup/changing-the-language/).
The texts generated by the hooks ("Last session recap", "played on", table headers) are in
English. To translate them, edit the strings in the files in `hooks/`.

### 4. Colors and theme

```yaml
theme:
  palette:
    - scheme: default          # light theme
      primary: white
      toggle: {icon: material/weather-night, name: Dark theme}
    - scheme: slate            # dark theme
      primary: black
      toggle: {icon: material/weather-sunny, name: Light theme}
```

Readers switch between the two schemes with the toggle in the header; `name` is its tooltip.
`primary` sets the header color: besides `white` and `black` you can use `red`, `indigo`,
`teal`, `deep orange`, `brown` and [many more](https://squidfunk.github.io/mkdocs-material/setup/changing-the-colors/).
Add `accent:` to change the color of links and hovered elements.

For finer styling (spacing, image styles), edit `overrides/stylesheets/extra.css`, which is
loaded through `extra_css`.

### Advanced customization

For further customization please refer to the section below: [Advanced mkdocs configurations](#advanced-mkdocs-configurations).

### Checking your changes

Before pushing, run a strict build. It fails on broken links, unknown arcs and YAML
errors, and prints the file and line that caused them:

```bash
mkdocs build --strict
```

## Project layout

```
docs/                     # YOUR campaign: starts as an empty skeleton
├── index.md              # home page (uses <!-- LAST_SESSION -->)
├── sessions/             # session recaps, one folder per season
│   └── season-01/
│       ├── index.md      # season page (uses <!-- TIMELINE -->)
│       └── s01-00.md     # one file per session (add yours here)
├── arcs/                 # one page per story arc (uses <!-- TIMELINE:ARC -->)
├── rules/                # house rules
├── magic-items/          # magic items
└── assets/               # images (covers, portraits)
example-docs/             # the example campaign, same structure, for reference
hooks/                    # the Python hooks behind the features above
overrides/                # theme customizations, including stylesheets/extra.css
_templates/session.md     # starting point for a new session (works with Obsidian)
mkdocs.yaml               # configuration of your wiki
example.yaml              # configuration of the example (inherits mkdocs.yaml)
```

Navigation is generated from the folder structure, so there is no menu to maintain:
add a file and it appears.

## Adding a session

Create a new file in the current season folder, e.g. `docs/sessions/season-02/s02-01.md`,
starting from `_templates/session.md`:

```markdown
---
session: S02-01
real_date: 2026-03-21
game_date: Bloom 20, 512 AC
arc: [TIDE]
cover: s02-01.webp
---

# The Title of the Session

What happened...
```

| Field       | Required | Description |
|-------------|----------|-------------|
| `session`   | no       | Short label shown in timelines. Defaults to the file name. |
| `real_date` | yes\*    | Real-world date the session was played (`YYYY-MM-DD`). Sorts the timelines and picks the last session. |
| `game_date` | no       | In-game date, free text in your setting's calendar. |
| `arc`       | no       | One arc code (`TIDE`) or a list (`[EMBER, TIDE]`). |
| `cover`     | no       | Image file name inside `docs/assets/`, shown under the title. |

\* A session without `real_date` still appears in timelines, but is never picked as the last session.

The page title is the first `# Heading` in the file. Season `index.md` files are not
treated as sessions.

## Markers

Put these HTML comments anywhere in a page. They are replaced when the site is built.

| Marker                   | Becomes |
|--------------------------|---------|
| `<!-- TIMELINE -->`      | Table of the sessions in the same folder as the page (use it in a season's `index.md`). |
| `<!-- TIMELINE:EMBER -->`| Table of all sessions tagged with arc `EMBER`, across every season. |
| `<!-- LAST_SESSION -->`  | Link to the most recent session (highest `real_date`). |

## Images

Put images in `docs/assets/`. Besides `cover:`, three CSS classes are available in
`overrides/stylesheets/extra.css`:

```markdown
![Mira](../assets/mira.webp){ .portrait width=160 }   <!-- floated right, e.g. character portraits -->
![Map](../assets/map.webp){ .full }                   <!-- full width -->
![Scene](../assets/scene.webp){ .hero }               <!-- full width header, what cover: uses -->
```

Prefer `.webp` and keep images under ~300 KB so the site stays fast.

## Writing with Obsidian

Open the repository folder as an Obsidian vault. The included `.obsidian/templates.json`
points the core **Templates** plugin at `_templates/`, so *Insert template → session* fills in
the frontmatter and today's date for you. Obsidian-style syntax works on the website too:

- `[[s01-01|link text]]` wiki links (via the `ezlinks` plugin)
- `> [!note]` callouts (via the `callouts` plugin)

## Publishing on GitHub Pages

The workflow in `.github/workflows/deploy.yml` builds and publishes the site on every push to `main`.

1. Push your repository to GitHub.
2. Wait for the first **Deploy** action to finish; it creates a `gh-pages` branch.
3. In **Settings → Pages**, set the source to *Deploy from a branch*, branch `gh-pages`, folder `/ (root)`.

Your wiki will be live at `https://YOUR-USERNAME.github.io/YOUR-REPO/`.


## Advanced mkdocs configurations


### Theme features

```yaml
theme:
  features:
    - navigation.sections   # top-level folders shown as groups in the sidebar
    - navigation.top        # "back to top" button
    - navigation.indexes    # a folder's index.md becomes the folder's own page
    - search.suggest        # completes words while typing in search
    - content.code.copy     # copy button on code blocks
```

Remove a line to turn a feature off, or add others from the
[Material documentation](https://squidfunk.github.io/mkdocs-material/setup/setting-up-navigation/).
Keep `navigation.indexes`: without it, each season's `index.md` shows up as an extra entry
inside its own section instead of being the section's page.

### Plugins and hooks

```yaml
plugins:
  - search
  - callouts   # Obsidian-style > [!note] callouts
  - ezlinks    # Obsidian-style [[wiki links]]

hooks:
  - hooks/windows_paths.py
  - hooks/timeline.py
  - hooks/game_date.py
  - hooks/background.py
  - hooks/last_session.py
```

Each hook is independent: delete its line to disable that feature.

| Hook               | Feature |
|--------------------|---------|
| `timeline.py`      | `<!-- TIMELINE -->` and `<!-- TIMELINE:CODE -->` tables |
| `last_session.py`  | `<!-- LAST_SESSION -->` link |
| `game_date.py`     | Subtitle with dates and party under each session title |
| `background.py`    | `cover:` header images |
| `windows_paths.py` | Fixes image and page links rewritten by `ezlinks` on Windows. Remove it only if you remove `ezlinks`. |

`timeline.py` and `last_session.py` look for sessions in `docs/sessions/`. If you rename
that folder, change `ROOT = "sessions"` at the top of both files.

### Markdown extensions

```yaml
markdown_extensions:
  - admonition        # !!! note / !!! tip boxes
  - pymdownx.details  # collapsible ??? boxes
  - tables
  - attr_list         # { .portrait width=160 } on images
  - md_in_html        # Markdown inside HTML blocks
  - toc:
      permalink: true # anchor link next to each heading
```

The example pages and the image classes rely on these, so keep them. More are listed in
the [Material reference](https://squidfunk.github.io/mkdocs-material/reference/).
